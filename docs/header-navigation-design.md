# トップナビゲーション改善 設計書

> 注記: 本設計書は `1.2.1` 時点のトップナビ改善を基礎とし、シングルス実装後の `/doubles` / `/singles` 有効化方針を反映したもの。試合形式ごとの詳細要件は `docs/singles-matchup-design.md` を正とする。

## 1. 目的

トップにあるカードを固定表示のナビゲーションへ変更し、現行の個別ボタンをメニューへ集約する。

この変更により、PC とスマホのどちらでも主要導線を常に見つけやすくしつつ、条件入力や対戦結果の表示領域を圧迫しすぎない構成にする。

本改善はアプリバージョン `1.2.1` で追加する。

## 2. 対象範囲

### 2.1 対象

- トップカードの sticky 固定化
- トップカード内の説明文削除
- PC 向け横並びメニューの追加
- スマホ向けハンバーガーメニューの追加
- 操作ガイドメニューへの `ホーム画面追加` / `アプリ共有` の集約
- 管理画面導線の PC メニュー化
- 既存 PWA インストール処理とアプリ共有ダイアログの再利用
- E2E テストのメニュー導線更新
- `package.json` / `package-lock.json` の version を `1.2.1` に更新する実装計画

### 2.2 対象外

- シングルス対戦表の生成機能
- 新しいページルーティングの追加
- 組合せ生成ロジック、共有 URL スキーマ、PDF / 印刷出力仕様の変更
- 管理画面本体のスマホ対応
- API / 管理機能の認証・権限仕様変更

## 3. 現状

トップカードは `src/app/page.tsx` のホーム画面 JSX 内に直接実装されている。

現在のトップカードには以下が含まれる。

- アプリアイコン
- `Tennis Matchup App`
- `ダブルスの対戦表と休憩者をまとめて作成。`
- PC 表示時の `ホーム画面追加` ボタン
- PC 表示時の `共有` ボタン
- PC 表示時の Gear Icon による `/admin` 導線

今回の変更では、説明文を削除し、単独ボタンと Gear Icon をメニュー構造へ置き換える。

## 4. 確定方針

| 項目 | 方針 |
| --- | --- |
| 固定方式 | `position: sticky` を採用する |
| 実装対象 version | `1.2.1` |
| PC メニュー位置 | `Tennis Matchup App` の下に横並びで配置する |
| スマホメニュー位置 | トップカード右側のハンバーガーボタンから開く |
| 説明文 | `ダブルスの対戦表と休憩者をまとめて作成。` を削除する |
| 対戦表(ダブルス) | `/doubles` へ遷移する有効リンクとして表示し、ダブルス表示中はアクティブ項目にする |
| 対戦表(シングルス) | `/singles` へ遷移する有効リンクとして表示し、シングルス表示中はアクティブ項目にする |
| 操作ガイド | `操作ガイド` + Chevron アイコンで表示する |
| ホーム画面追加 | 操作ガイド配下へ移動し、現行の単独ボタンは廃止する |
| アプリ共有 | 操作ガイド配下へ移動し、現行の単独共有ボタンは廃止する |
| 管理用 | PC の横並びメニューに表示し、`/admin` へ遷移する |
| スマホでの管理用 | 表示しない |
| スマホメニュー閉じる操作 | ハンバーガーボタンの再押下で閉じる |

## 5. sticky と fixed の比較

### 5.1 sticky を採用する理由

`sticky` は元のレイアウト上の高さを保持したまま、スクロールで上端に達した後だけ上部に残る。

このアプリでは、条件フォームや対戦結果のカードが縦に続くため、トップナビが本文を隠さないことを優先する。`sticky` であれば、トップカード分の高さが自然に確保され、フォーム先頭や完了メッセージとの重なりを抑えやすい。

### 5.2 fixed を採用しない理由

`fixed` は viewport に対して常時固定されるため、ナビは常に同じ位置に表示できる。一方で、要素が通常レイアウトから外れるため、本文側にヘッダー高さ分の `padding-top` を追加する必要がある。

また、以下の調整が増える。

- 生成完了メッセージとの z-index 競合
- 共有ダイアログ、インストール案内、コート数調整ダイアログとの重なり
- スマホブラウザのアドレスバー表示変化や safe area との位置ずれ
- PC / スマホでヘッダー高さが変わった場合の余白再計算

今回の要件では「スクロール中に上部へ残る」ことが満たせればよいため、`sticky` を採用する。

## 6. UI 仕様

### 6.1 PC 表示

トップカードは以下の構造にする。

```txt
[icon] Tennis Matchup App
       対戦表(ダブルス)  対戦表(シングルス)  操作ガイド v  管理用
```

`対戦表(ダブルス)` / `対戦表(シングルス)` はそれぞれ `/doubles` / `/singles` へ遷移するリンクにする。現在表示中の試合形式が分かるよう、該当項目に `aria-current="page"` とアクティブ表示を付ける。

`操作ガイド` を開くと以下を表示する。

```txt
ホーム画面追加
アプリ共有
```

`ホーム画面追加` は、ブラウザが `beforeinstallprompt` を提供している場合は既存の `promptInstall()` を呼ぶ。インストールプロンプトを出せない環境では、既存の案内ダイアログまたは同等の案内表示へ誘導する。

`アプリ共有` は既存の `AppShareDialog` を開く。

`管理用` は `/admin` へ遷移するテキストメニューにする。

### 6.2 スマホ表示

トップカードは以下の構造にする。

```txt
[icon] Tennis Matchup App                         [menu]
```

ハンバーガーメニューを開くと、トップカード直下にメニューを重ねて表示する。メニューは通常レイアウトから外し、開閉しても `Conditions` パネルの位置を下げない。

スマホメニューには以下を表示する。

```txt
対戦表(ダブルス)
対戦表(シングルス)
操作ガイド v
  ホーム画面追加
  アプリ共有
```

スマホでは `管理用` を表示しない。`/admin` に直接アクセスされた場合の PC 専用表示方針は既存のままとする。

## 7. コンポーネント設計

トップナビは `src/app/page.tsx` から切り出す。

候補:

```txt
src/components/layout/AppHeaderNav.tsx
```

`page.tsx` は以下を渡す責務に留める。

- `canPromptInstall`
- `isInstalled`
- `onInstall`
- `onOpenInstallGuide`
- `onOpenAppShare`

`AppHeaderNav` は表示、メニュー開閉、PC / スマホ切替、アクセシビリティ属性を担当する。

既存の `AppShareDialog`、`InstallGuideDialog`、`usePwaInstallPrompt` は再利用する。生成条件、結果表示、印刷、PDF、共有 URL 復元の状態管理には触れない。

## 8. 状態とアクセシビリティ

### 8.1 状態

追加する UI 状態は以下に限定する。

- 操作ガイドドロップダウンの開閉
- スマホハンバーガーメニューの開閉
- スマホメニュー内の操作ガイド開閉
- インストール案内ダイアログの開閉が未接続の場合は、その開閉状態

### 8.2 アクセシビリティ

- ハンバーガーボタンには `aria-label` と `aria-expanded` を付与する。
- 操作ガイドボタンには `aria-haspopup="menu"` と `aria-expanded` を付与する。
- スマホのハンバーガーボタンは開閉トグルとし、開いている場合は `aria-label="メニューを閉じる"` を付与する。
- `Escape` キーで開いているメニューを閉じられるようにする。
- メニュー項目はボタンまたはリンクとして意味に合った要素を使う。
- `対戦表(ダブルス)` / `対戦表(シングルス)` は現在表示中の形式にだけ `aria-current="page"` を付ける。
- スマホメニュー内の試合形式リンクは `Link` の `onNavigate` でメニューを閉じ、ナビゲーション前にリンク自体を unmount しない。

## 9. テスト設計

### 9.1 テスト観点

機能観点:

- PC 表示で横並びメニューが表示されること。
- スマホ表示でハンバーガーメニューが表示されること。
- 操作ガイドを開くと `ホーム画面追加` と `アプリ共有` が表示されること。
- `アプリ共有` から既存の共有ダイアログが開くこと。
- PC の `管理用` から `/admin` へ遷移できること。
- スマホメニューに `管理用` が表示されないこと。

非機能観点:

- sticky ヘッダーがスクロール中に上部へ残ること。
- ヘッダーが条件フォーム、生成完了メッセージ、各種ダイアログを不自然に隠さないこと。
- メニュー開閉が低速端末でもレイアウトシフトを起こしにくいこと。
- PC / スマホ境界幅で表示が崩れないこと。

データ観点:

- 対戦条件の入力値、生成結果、seed、共有 URL、PDF / 印刷出力に変更がないこと。
- `AppShareDialog` の共有 URL が従来どおり `APP_SHARE_URL` を使うこと。
- バージョン表示が `package.json` の `1.2.1` を参照すること。

UI 観点:

- `ダブルスの対戦表と休憩者をまとめて作成。` が表示されないこと。
- `Tennis Matchup App` の下に PC メニューが横並びで表示されること。
- `対戦表(シングルス)` が `/singles` へ遷移でき、シングルス表示中にアクティブ表示になること。
- `操作ガイド` に Chevron アイコンが表示されること。
- スマホメニューを開いても `Conditions` パネルが下へ移動しないこと。

### 9.2 正常系

- PC 幅でトップナビを表示し、操作ガイドからアプリ共有を開く。
- PC 幅で `管理用` を押し、`/admin` へ遷移する。
- スマホ幅でハンバーガーメニューを開き、ハンバーガーボタン再押下で閉じる。
- スマホ幅で操作ガイドを開き、アプリ共有を開く。

### 9.3 異常系

- `beforeinstallprompt` が発火しない環境でも、`ホーム画面追加` の操作で破綻しないこと。
- 共有 API が使えないブラウザでも、既存のコピー / QR 表示導線が使えること。
- `/admin` 直接アクセス時、スマホ幅では管理画面本体を表示しない既存挙動を維持すること。

### 9.4 境界値

- PC / スマホ切替境界の直前・直後で、PC メニューとスマホメニューが同時表示されないこと。
- 長い日本語ラベルが折り返してボタン高さやカード高さを不自然に変えないこと。
- 画面幅が狭いスマホでもハンバーガーボタンとメニュー項目が重ならないこと。

### 9.5 状態遷移

| 初期状態 | 操作 | 期待状態 |
| --- | --- | --- |
| PC / メニュー閉 | 操作ガイドを押す | 操作ガイドメニューが開く |
| PC / 操作ガイド開 | 外側クリックまたは Escape | 操作ガイドメニューが閉じる |
| スマホ / メニュー閉 | ハンバーガーを押す | スマホメニューが開く |
| スマホ / メニュー開 | ハンバーガーボタン再押下または Escape | スマホメニューが閉じる |
| スマホ / メニュー開 | アプリ共有を押す | メニューが閉じ、共有ダイアログが開く |
| スマホ / メニュー開 | 対戦表(シングルス)を押す | `/singles` へ遷移し、シングルス条件入力へ切り替わる |

### 9.6 フレーク対策

- sticky 判定はピクセル完全一致ではなく、スクロール後もヘッダーが viewport 上部付近に存在することを確認する。
- ドロップダウン表示は animation 完了待ちに依存せず、role / test id の可視性で確認する。
- 同一実機や同一ブラウザセッションで E2E を並列実行しない。
- 失敗時にスクリーンショット、trace、console log を取得できる Playwright 設定を使う。

## 10. 影響範囲

| 領域 | 影響 |
| --- | --- |
| ホーム画面 | トップカードとナビ導線を変更する |
| PWA | インストール処理は再利用し、入口だけ変更する |
| アプリ共有 | `AppShareDialog` は再利用し、入口だけ変更する |
| 管理画面 | PC 導線の表示形だけ変更する。`/admin` 本体は変更しない |
| 組合せ生成 | 変更しない |
| 共有 URL / PDF / 印刷 | 変更しない |
| README / 設計書 | Gear Icon 前提をトップナビの `管理用` 導線へ更新する |

## 11. 実装順序

1. version を `1.2.1` に更新する。
2. `AppHeaderNav` を追加する。
3. `page.tsx` からトップカード JSX を `AppHeaderNav` へ移動する。
4. `InstallGuideDialog` が未接続の場合は、操作ガイドから開けるように接続する。
5. PC メニューとスマホメニューの表示制御を追加する。
6. 既存 E2E の `open-share-dialog-button` 前提を新しいメニュー導線へ更新する。
7. README と関連設計書の導線記述を更新する。
8. `npm run lint`、`npm test`、`npm run build`、Playwright の対象 E2E を実行する。

## 12. 優先度とリスク

まず防ぐべき不具合:

- 共有導線が消えてアプリ共有できなくなる。
- スマホでメニューを閉じられなくなる。
- sticky ヘッダーが条件入力欄や生成完了メッセージを隠す。
- PC で管理画面導線が失われる。

優先度:

| 区分 | 内容 |
| --- | --- |
| 致命 | 生成、共有 URL 復元、PDF / 印刷が壊れる |
| 重大 | PC / スマホの主要メニューが開けない、閉じられない |
| 重大 | `/doubles` / `/singles` の切替で試合形式が切り替わらない |
| 軽微 | バッジ余白、ホバー表現、影の強さなどの見た目調整 |

再発防止:

- メニュー項目名と表示有無を E2E で明示的に検証する。
- 共有ダイアログ起動は `AppShareDialog` の表示まで確認する。
- 管理用は PC 表示のみ、スマホ非表示を別々に検証する。

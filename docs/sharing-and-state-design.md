# 共有URL・画面状態・印刷データの現行設計

## 1. 対象と実装

通常の対戦表を条件と採用seedから再生成する共有、試合形式別の画面状態保持、印刷プレビューへのデータ受け渡しを扱う。

- URL生成・復元: [shareMatchup.ts](../src/features/matchmaking/application/shareMatchup.ts)
- 画面・進行制御: [page.tsx](../src/app/page.tsx)
- 状態保持: [matchupStore.ts](../src/stores/matchupStore.ts)
- 共有UI: [AppShareDialog.tsx](../src/components/share/AppShareDialog.tsx)、[ResultShareDialog.tsx](../src/components/share/ResultShareDialog.tsx)

## 2. 共有の種類

| 操作 | 対象URL | 内容 |
| --- | --- | --- |
| トップナビの共有 | アプリ公開URL | アプリを紹介する。対戦表や入力条件は含めない |
| 結果欄の共有 | 現在のoriginの `/doubles` / `/singles` とquery | 条件と採用seedから同じ対戦表を再生成する |
| 印刷・PDFのQR | 出力モデルに設定した対戦表URL | 対戦表を別端末で表示する |

共有ダイアログでは、端末の共有メニュー、URLコピー、QR表示を利用できる。Web Share APIが使えない環境や呼び出し失敗時にはURLコピー・QR表示を案内する。クリップボード権限はブラウザに依存する。

## 3. 対戦表URLの契約

新規生成URLのversionは `1.20`。

| Query | 用途 |
| --- | --- |
| `shared=1` | 共有復元を有効にする |
| `v` | queryスキーマのversion |
| `format` | `doubles` / `singles` |
| `participants` | 人数 |
| `courts` | コート数 |
| `rounds` | ラウンド数 |
| `seed` | 最適化後に採用されたseed |
| `mode` | 対戦モード |
| `female`, `male` | ダブルスの性別優先モードのみ付与する男女別人数 |
| `event` | 開催名。指定がある場合のみ付与 |

参加者名・IDの配列、対戦結果そのもの、生成時刻、実施済み状態、途中参加・退出履歴はURLに含めない。UIの番号参加者を `01` 起点で再構築し、性別優先モードでは女性から先に採番する。開催名はURLから読めるため、URLは秘匿用の保存先ではない。

復元では候補seed探索を行わず、`generateMatchup(conditions, seed)` を直接呼ぶ。`generatedAt` は復元時刻になる。query versionはスキーマ互換のための値であり、過去の生成アルゴリズムを固定して保存するものではない。

### 3.1 互換

| Version | 復元 |
| --- | --- |
| `1.00` | ダブルス・通常モード。形式と性別条件を含まない旧URL |
| `1.10` | 対戦モードと性別人数を読み込む。`format` がなければダブルス |
| `1.20` | 試合形式を含む現行URL。`format` がなければダブルス |
| その他 | 復元エラーを表示する |

通常表示はrouteの形式を使うが、共有URLはqueryで復元した形式を優先する。`/singles` で `format=doubles` が渡されればダブルスとして表示する。共有復元の入力エラーでは案内を表示し、復元結果を保存しない。

### 3.2 途中再作成の制限

`resultSource = "continuation"` の場合、対戦表共有ボタンを無効化し、印刷・PDFの共有QRも付けない。固定ラウンドと途中変更を現在のURLスキーマで再現できないためである。トップナビのアプリURL共有と、途中再作成した対戦表の印刷・PDF出力は利用できる。通常の全体再作成に戻れば対戦表URL共有を利用できる。

## 4. 状態と保存範囲

| データ | 保持先 | 保持範囲 |
| --- | --- | --- |
| 生成済み条件・結果・seed・再作成回数 | Zustandの `byFormat` | 同じ画面セッションの形式切替中。reload / 再起動では消える |
| 今後の生成対象ID・実施済み数・ロック済み数・結果種別 | 同じ形式別store | ダブルス / シングルスで独立。reload / 再起動では消える |
| 未生成のフォーム編集・途中変更下書き | コンポーネント内state | 画面切替で保持しない |
| 印刷モデル | localStorageの `tennis-matchup-print-model-v1` | 最後に渡した1件。自動削除や世代管理はない |
| PWAスプラッシュ表示済み | sessionStorage | 同一sessionでの重複表示を抑える。対戦表保存には使わない |
| 静的画像・フォント・Next.jsアセット | Service WorkerのCache Storage | 静的アセットのみ。対戦表復元には使わない |

形式切替で復元するフォームは生成済み結果の条件を優先し、結果がなければstoreの条件を使う。画面で編集しただけの未生成値はstoreへ永続化しない。Firestoreはアカウント・APIキー・ログ・rate limit用であり、UIの対戦表を保存しない。

## 5. 印刷プレビューの受け渡し

[usePrintPreview.ts](../src/hooks/usePrintPreview.ts) が印刷モデルをlocalStorageへ書き込み、`/print` を別タブで開く。[印刷画面](../src/app/print/page.tsx) はstorageイベントを監視するため、同じoriginの別タブで新しいプレビューを開くと既存プレビューの内容も更新される。

保存データがない場合は `印刷対象のデータがありません` と表示する。印刷データのJSON破損に対する復旧UIは未実装。複数の対戦表を固定して残す用途にはPDF出力または印刷を利用する。

## 6. テスト設計

### 6.1 観点

- 機能: アプリ共有と対戦表共有の区別、seed直接再現、途中再作成時の制限、印刷受け渡し
- データ: version互換、形式・性別人数・seedの検証、形式別状態の独立、保存しないデータの確認
- UI: 共有API / コピー権限による環境差、エラー案内、共有無効表示、PC / スマホの操作
- 非機能: 永続保存との混同防止、複数タブの上書き、QR生成の非同期処理、reload時の状態初期化

### 6.2 ケースと意図

| 区分 | 検証 | 意図 |
| --- | --- | --- |
| 正常系 | 通常 / 性別優先 / シングルスのURL往復でrounds・stats・score・seedを比較 | 候補探索を再実行せず対戦内容を復元する |
| 正常系 | `1.00` / `1.10` の共有URLを復元 | 既存URLの利用を維持する |
| 異常系 | 未対応version、形式不正、ダブルス性別人数不一致 | 不正な共有条件を結果として表示しない |
| 異常系 | Web Share API利用不可、コピー失敗、印刷JSON破損 | 環境差や保存データ破損の切り分けをする。JSON破損の復旧UIは未実装 |
| 境界値 | 形式別人数最小・最大、面数 / 回数上限、男女0人、seed 0 / 負数 | URLの許容範囲を確認する。共有seedは非負整数で、APIの整数制約とは異なる |
| 状態遷移 | ダブルス生成→シングルス生成→ダブルスへ戻る | 生成済み状態・進行状態を混ぜない |
| 状態遷移 | 途中再作成→共有無効 / QRなし→全体再作成 | 結果種別に応じた共有可否を確認する |
| 状態遷移 | reload、別タブの印刷モデル上書き | メモリ保持とlocalStorageの寿命・競合を区別する |

テストごとにstore、localStorage、sessionStorageを初期化し、既存データに依存しない前提を用意する。再現性の比較から `generatedAt` を除く。同一実機のブラウザ操作は直列に行い、失敗時はquery、採用seed、結果種別、storage状態、ブラウザとviewportを証跡にする。

初回の文書照合では既存単体テストを実行し、E2Eは未実施。後続のPR対応ではPWA関連5ケースをChromiumで検証したが、共有ダイアログ・複数タブ・クリップボード権限を含むE2Eは未実施。全ケースが自動化済みという意味ではない。検証の時点と範囲は [確認記録](implementation-audit-2026-10-06.md) を参照。
